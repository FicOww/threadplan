# 业务评估与复现

实际成绩、模型路线和局限集中在 [VALIDATION](../reports/VALIDATION.md)。所有现有材料均为开发数据，不是独立人工金标或生产盲测；真实模型推理、模拟读取与真实 Test 日历执行分别报告。

## 数据与版本

- candidate_v03.*.jsonl：历史 11 项构造任务，原输入/fixture/标签不改。历史结果为基础6＋扩展4＋专项1，不冒充一次新全批运行。
- target_v1.json：当前评测清单，引用原输入/fixture和独立新版预期；accept05 因默认30分钟由 WAIT 改 CREATE。新版标签在首次新版推理前冻结，原标签保留。
- target_gaps.*.jsonl：10项新增构造开发任务，覆盖未确认、未记录改期、多活动部分等待、个人退出、无标题、相似候选等待/补详情成功消歧、第三方安排、不支持邀请及日历备注中的权限注入。原作者/时间均为明确构造，不冒充用户资料；标签在该组首次推理前冻结。
- duration_policy.*.jsonl：显式用户配置时长专项，不计入11项主回归。

```powershell
python -B -X utf8 scripts/evaluate_simulated_chats.py --dataset target_v1 --provider codex --max-calls 24
python -B -X utf8 scripts/evaluate_simulated_chats.py --dataset target_gaps --provider codex --max-calls 24
```

默认只预览，显式 --run 才推理；必须明确 provider，不能自动回退。每例最多3次尝试、每批最多24次；未完成原样报告。模型仅获得原消息、必要可信配置与实际有界读取，不接收参考、场景名注释、native目标ID或评分结果。工具 fixture 可分别提供列表和详情快照，缺省为同一来源数据。

运行复制冻结材料，记录 Git/工作区、源码与规则哈希、输入、原输出、每次读取/模型错误、耗时和提供方用量。人工/宿主复核另写 sidecar，原始失败不覆盖。更换规则/模型后完整重跑，不把局部成功拼成全批。

## 评分与复核

先检查错误动作、目标、时间、未请求字段、重复和越权；再核对业务信息是否保留。评分器检查操作、真实fixture目标、必要决策和具体约束，不能证明语义正确。FAILED/未完成读取不当成功；工程挡住的错误提议不算模型成功。允许多种正确不写结果的样本在预期中显式 terminal_one_of，不能事后为某次输出放宽。

默认时长只能由工程应用并记录来源。原文已给完整替换备注时要求完整替换；局部修改才保留其他内容。复核须检查原文语义、实际查询、候选排除依据、字段范围与默认来源，不能只看 score=true。用量未提供保持未知，Codex CLI 启动和上下文开销不换算生产 API 价格。

--compare-direct 仅比较“在主链已取得同一证据上再做一次判断”，不包含检索，不能当完整的一次调用架构。此前A/B/C架构对照结果仅在VALIDATION记录；旧结构化抽取实现、旧Git对象和依赖它的实验脚本不在公开快照内，因此不能从本仓库完整复现旧版对照。不为历史对照保留第二条生产主链。

## Skill 与真实执行

scripts/evaluate_skill_agent.py --prepare <新版ZIP> --dataset target_v1 建立隔离的已打包工具前向环境；宿主仅收到 Skill、原文与实际查询返回。--score 在决策后独立读取标签，评分和宿主复核分别保存。宿主实际模型/身份暴露程度、是否已经见过开发材料必须如实报告，不称独立盲测。

scripts/verify_skill.py 默认预览，--run 仅在已有明确授权的私有 Test 日历进行一条标记记录的连续新增/改期/取消、读回和重复回执核验。它是零模型调用的构造执行验收，不是语义端到端成绩。恢复脚本保留只读恢复测试，不盲重发未知 CREATE。

## diversity50-v1 构造开发集

固定50条：原11+10+1全部保留，新增28条；构造来源、原文件SHA与split保存在 diversity50.json/catalog。新案例覆盖跨午夜、DST重复/不存在时间、时区等价、默认/明确时长、字段局部变更、语义取消、歧义、多活动、团队范围、条件同意、注入及不支持的实质需求。48条语义开发参考与2条读取FAILED/PARTIAL技术契约分别统计。无真实用户数据或独立人工审标；既有案例已经参与开发，不称盲测。

聚合结果和验证范围见 [VALIDATION](../reports/VALIDATION.md)。语义案例与技术契约使用各自的统计口径。

`python -B -X utf8 scripts/evaluate_diversity50.py --provider codex`预览；显式加`--run`按冻结顺序10批×5执行，要求干净提交，每批最多15次、每例最多3次。全部使用同一源码/规则/数据哈希，不回放旧输出、不增加对照模型、不写真实日历。原始输出、读取、失败与每批回执留在runs。technical_failure_contract仅检查无写入、实际失败或部分读取、失败暴露，不纳入语义正确分母。自动约束通过须另做原文与真实模型输出复核；只因工程拒绝错误建议不能算语义成功。
